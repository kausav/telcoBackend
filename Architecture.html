INGENII Telecom Synthetic Data Generator

Current architecture: official TM Forum, 3GPP and MEF machine-readable data models are the semantic source of truth; INGENII generation profiles are behavior-only overlays; Gemini interprets scenarios; a deterministic compiler builds the executable schema; and deterministic validation enforces the final contract.

Core rule: official models define what a field means. INGENII generation policies define how a synthetic value may be sampled. The two are intentionally separate.

Normalized JSON files under runtime_data are generated indexes/cache artifacts. They are not presented as official standards documents and are not hand-authored semantic sources.

2. Official model ingestion

TM Forum

Official TM Forum OpenAPI/data-model artifacts are synchronized from resources/telecom/standards/official_sources.json. Low Balance & Top-up additionally uses the bundled TMF654 and TMF629 v4.0.0 Swagger artifacts as reproducible domain sources; the other TM Forum sources retain runtime synchronization.

MEF

MEF machine-readable YAML/JSON Schema archives are synchronized at pinned Git commits for the MEF 125 Subscriber Ethernet and MEF 139 Internet Access schema sets.

3GPP

The current manifest pins 3GPP TS 32.298 Release 19 v19.4.0 and parses the machine-processable ASN.1 structures into the runtime registry.

The manifest preserves source URL and SHA-256 metadata. A deployment can rebuild the runtime registry from the same pinned inputs.

3. Generation profiles: policy, not semantics

The directory resources/telecom/generation_profiles/ now contains one policy file: telecom_official_generation_v2.json. Its targets use the exact identity source_id + model + field. Legacy keys such as recharge.recharge_amount are no longer accepted.

{
  "source_id": "tmf654_v4",
  "model": "TopupBalance",
  "field": "requestedDate",
  "generator": "timestamp",
  "params": {"lookback_days": 365}
}
Important: a distribution such as “95% completed” is an INGENII synthetic-data assumption, not a statement that TM Forum mandates that operational frequency. The standard supplies semantics and constraints; the profile supplies sampling policy.

There is no application-level 30–35 variable ceiling. For most domains, breadth is driven by the scenario and approved registry resolution. Low Balance & Top-up compiles the complete material scalar catalog from the bundled TMF654/TMF629 primary business models, excluding bucket-scoped and transport/display metadata, then removes semantic duplicates with MongoDB variables. This maximizes analytical coverage without inventing executable fields.

For Low Balance & Top-up, the application contract always includes customer_id, account_id and msisdn. account_id and msisdn must be supplied by MongoDB; customer_id may be official TMF629 or MongoDB and, when MongoDB-owned, must use the exact cust- + 8-digit contract.

5. Gemini boundary

Gemini receives

scenarioType, industryType, domain, businessScenario, useCase, typeOfData and country, plus constrained official-model grounding.

Gemini does not own

Official field definitions, types, relationships, generators, formulas, or arbitrary telecom vocabulary. The LLM output is validated and resolved against the official registry before it becomes executable.

entity_key may still be supplied in the API for grouping/output behavior, but it is not part of the Gemini intent message.

11. Cross-platform server runtime

Application code
        ↓
OS-independent pathlib paths
        ↓
Persistent writable RUNTIME_DATA_DIR
        ↓
Official-source sync / normalized index / MongoDB registry
        ↓
Native OS-level bootstrap lock
        ↓
Safe with Windows Server, Linux, and container deployments

Official archive extraction uses the operating-system temporary directory rather than the application/runtime tree. Registry bootstrap uses an OS-level process lock so multiple Uvicorn workers cannot race during official-source synchronization or registry rebuild.

12. Operations

# install
pip install -r requirements.txt

# start API
uvicorn server:app --reload

# force refresh of official model inputs and rebuild runtime registry
python scripts/ingest_standards.py --force

Generated values use stochastic sampling. The architecture persists the standards lineage and confirmed contract; bit-for-bit dataset reproducibility requires an explicit generation seed, which is not currently part of the public agentic API.

Design invariant: the official model remains authoritative. Optional generation-policy references that do not exist in the active official model are logged and skipped; a target explicitly marked required=true fails registry construction. The system never silently changes official semantic definitions.
